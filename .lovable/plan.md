
## Цель

Сделать так, чтобы фотографии галереи на странице Бари (а в будущем — и других направлений) загружались через панель администратора, а подпись об авторстве/лицензии появлялась только для тех фото, у которых она действительно нужна, и исчезала автоматически, когда вы замените все фото на собственные.

---

## Этап 1. Только Бари (делаем сейчас)

### 1. База данных
Новая таблица `destination_gallery_images` со связкой к направлению:
- ссылка на направление (по slug, для совместимости со страницей Бари, которая уже грузит данные по slug)
- URL фото (из бакета `public-images`)
- alt-текст на RU и RO
- автор (опционально, текст)
- лицензия (опционально, текст, напр. «CC BY-SA 4.0»)
- ссылка на источник (опционально)
- порядок отображения (число для сортировки)
- даты создания/обновления

Доступ: публичный SELECT (фото показываются всем), INSERT/UPDATE/DELETE только для admin.

### 2. Админка — раздел «Галерея» у направления
В существующей форме редактирования направления (`/admin/destinations/:id`) добавляется новая секция «Фотогалерея»:
- список загруженных фото с миниатюрой, alt-текстами и (если есть) полями автор/лицензия/источник
- кнопка «Добавить фото» — открывает существующий `ImageUpload` (загружает в бакет `public-images/destinations-gallery/`)
- для каждого фото: редактирование alt-текстов и полей атрибуции, удаление, перестановка порядка (стрелки вверх/вниз)
- поля автор/лицензия/источник — необязательные. Пустые → атрибуция для этого фото не показывается.

### 3. Страница Бари
- Захардкоженный массив из 4 фото удаляется.
- Галерея читается из новой таблицы через server function в том же лоадере, где уже грузится `destination`.
- Подпись об атрибуции формируется автоматически: проходим по фото галереи, собираем уникальные пары «автор — лицензия», и если их нет ни у одного фото, подпись просто не показывается. То есть как только вы удалите все фото с Wikimedia и оставите только свои (без указания автора/лицензии) — надпись исчезнет сама, без правок кода.
- Существующие 4 фото из Wikimedia мы заодно перенесём в новую таблицу через миграцию данных, чтобы страница не «опустела».

### 4. Что НЕ меняется
- Лейаут галереи (десктоп — сетка 4 миниатюр справа от hero, мобайл — горизонтальная лента) остаётся как есть.
- Лайтбокс (открытие на полный экран, упирание в края на мобайле) — без изменений.
- Все остальные секции страницы Бари — без изменений.

## Этап 2. Расширение на другие направления (потом, отдельной задачей)

После того как вы протестируете админку на Бари и убедитесь, что всё работает как надо:
1. Те же поля галереи появляются в форме любого направления автоматически — таблица уже универсальная (привязана к slug направления).
2. Остаётся переписать страницы остальных направлений (`/destinations/...`) на тот же шаблон чтения галереи, что и Бари.

Это уже будет чисто механическая работа: модель данных и админка готовы с первого этапа.

## Ответы на ваши вопросы прямо

- **Надпись о лицензии** — она сейчас в коде потому, что Wikimedia требует указывать автора. После реализации Этапа 1 эта подпись будет автоматической: она появляется, только если у хотя бы одного фото в галерее заполнены поля «автор» или «лицензия». Удалите все фото с Wikimedia и загрузите свои без заполнения этих полей — подпись пропадёт сама, без вмешательства в код.
- **Загрузка фото через админку** — да, реализуется в Этапе 1 через ту же форму, где вы сейчас редактируете направление Бари. Используется уже существующий загрузчик файлов (тот же, что для главной обложки).
- **Удаление старых фото** — после Этапа 1 вы сможете удалить любое из 4 текущих фото прямо в админке (без правок кода), и сразу же загрузить вместо него своё.

## Технические детали (для справки)

- Миграция: `CREATE TABLE public.destination_gallery_images` + GRANT + RLS (public SELECT, admin write через `has_role`).
- Server functions: `listGalleryByDestinationSlug` (публичный read), `adminListGallery`, `adminSaveGalleryImage`, `adminDeleteGalleryImage`, `adminReorderGallery` (под `requireSupabaseAuth` + проверка роли admin).
- Storage: путь `destinations-gallery/{slug}/` внутри существующего бакета `public-images`.
- Перенос текущих 4 фото — отдельным INSERT после миграции, чтобы страница Бари не оказалась без галереи на момент деплоя.
